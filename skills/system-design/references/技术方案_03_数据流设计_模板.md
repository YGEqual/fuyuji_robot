## 二、数据流向图

### 2.1 整体数据流

```mermaid
flowchart TB

    end

        DB[(MySQL)]
        CACHE[(Redis)]

    end
    subgraph 数据出口
        API_OUT[API返回]
        MQ_OUT[消息发送]
        EXPORT[数据导出]
    end
    API --> PROCESS
    MQ_IN --> PROCESS
    SYNC --> PROCESS
    PROCESS --> VALIDATE --> TRANSFORM
    TRANSFORM --> DB & CACHE & S3
    DB & CACHE --> API_OUT
    DB & CACHE --> MQ_OUT
    DB --> EXPORT
```

### 2.2 核心数据流

> 最重要的业务数据是怎么流转的。

```mermaid
sequenceDiagram
    participant 用户
    participant API
    participant Service
    participant Cache
    participant DB
    participant MQ
    用户->>API: 请求数据
    API->>Service: 处理
    Service->>Cache: 查缓存
    alt 缓存命中
        Cache-->>Service: 返回
    else 缓存未命中
        Service->>DB: 查DB
        DB-->>Service: 返回
        Service->>Cache: 写缓存
    end
    Service->>MQ: 发送变更消息
    Service-->>API: 返回
    API-->>用户: 响应
```

## 四、缓存设计

### 4.1 缓存策略总览

| 缓存用途 | 缓存类型 | 过期策略 | 更新策略 |
|---------|---------|---------|---------|
| 热点数据 | Redis String | 定时过期 | 写时更新 |
| 计数器 | Redis Incr | 不过期 | 实时累加 |
| 会话数据 | Redis Hash | 滑动过期 | 访问续期 |

### 4.2 缓存 Key 设计

| Key 格式 | 数据内容 | 过期时间 | 数据大小 | 更新触发 |
|----------|---------|---------|---------|---------|
| `业务:模块:id` | | 秒 | KB/MB | |
| `业务:模块:hash` | | | | |

### 4.3 缓存一致性方案

| 场景 | 一致性要求 | 方案 | 具体实现 |
|------|-----------|------|---------|
| 读多写少 | 最终一致 | Cache-Aside | 先查缓存，没有查DB并回写 |
| 写多读少 | 强一致 | Write-Through | 写缓存+写DB原子操作 |
| 高并发写 | 最终一致 | Write-Behind | 先写缓存，异步写DB |

### 4.4 缓存击穿/穿透/雪崩防护

| 问题 | 防护方案 | 具体实现 |

| 缓存击穿 | 分布式锁/永不过期 | |
| 缓存雪崩 | 随机过期时间/熔断降级 | |
