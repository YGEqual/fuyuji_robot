## 一、可观测性目标

### 1.1 核心目标

> 代码运行起来后，能"看到"什么？

| 目标 | 说明 | 本次覆盖 |
|------|------|---------|
| 能看到请求处理过程 | 每个请求的完整链路 | ✓ |
| 能看到业务状态变化 | 关键业务节点的状态流转 | ✓ |
| 能看到异常和错误 | 错误发生时能快速定位 | ✓ |
| 能看到性能瓶颈 | 慢在哪个环节 | ✓ |
| 能看到资源消耗 | CPU/内存/连接数等 | ✓ |

### 1.2 可观测性三支柱

| 支柱 | 工具 | 用途 |
|------|------|------|
| 日志（Logs） | ELK/日志平台 | 排障、审计 |
| 指标（Metrics） | Prometheus/Grafana | 监控、告警 |
| 链路（Traces） | Jaeger/SkyWalking | 链路追踪、性能分析 |

## 二、日志设计

### 2.1 日志规范

| 项目 | 规范 |
|------|------|
| 日志框架 | Logback/Log4j2 |
| 日志格式 | JSON 结构化 |
| 日志级别 | ERROR > WARN > INFO > DEBUG |
| 日志输出 | 控制台 + 文件（容器环境只输出控制台） |

### 2.2 日志级别使用

| 级别 | 使用场景 | 示例 |
|------|---------|------|
| ERROR | 影响业务的异常，需要立即关注 | 外部服务调用失败、数据库异常 |
| WARN | 潜在问题，不影响业务但需要关注 | 降级触发、缓存未命中率高 |
| INFO | 关键业务节点、外部调用 | 请求入口、业务状态变更、外部调用 |
| DEBUG | 开发调试信息（生产环境关闭） | 中间变量、详细流程 |

### 2.3 关键日志打点

| 打点位置 | 日志内容 | 级别 | 示例 |
|---------|---------|------|------|
| 接口入口 | 请求参数 | INFO | `[API:xxx] 收到请求, traceId={}, userId={}, params={}` |
| 接口出口 | 响应结果 + 耗时 | INFO | `[API:xxx] 响应完成, traceId={}, 耗时={}ms, code={}` |
| 外部调用前 | 请求参数 | INFO | `[CALL:xxx] 请求, traceId={}, params={}` |
| 外部调用后 | 响应结果 + 耗时 | INFO | `[CALL:xxx] 响应, traceId={}, 耗时={}ms, result={}` |
| 异常 | 完整异常栈 + 上下文 | ERROR | `[API:xxx] 处理失败, traceId={}, userId={}, error=` |
| 业务节点 | 状态变化 | INFO | `[BIZ:xxx] 状态变更: {} -> {}, traceId={}, reason={}` |

### 2.4 traceId 传递

| 链路段 | 传递方式 | 生成规则 |
|--------|---------|---------|
| 客户端 → 网关 | HTTP Header: X-Trace-Id | 客户端生成，或网关生成 |
| 服务间调用 | HTTP Header: X-Trace-Id | 透传 |
| 异步消息 | MQ Header / 消息体字段 | 透传 |
| 线程池 | MDC 传递 | InheritableThreadLocal |

## 三、监控设计

### 3.1 应用监控

| 监控项 | 指标 | 采集方式 | 采集频率 |
|--------|------|---------|---------|
| 接口 QPS | 请求数/秒 | Prometheus | 15s |
| 接口响应时间 | P50/P95/P99 | Prometheus | 15s |
| 接口错误率 | 错误数/总请求数 | Prometheus | 15s |
| 并发数 | 正在处理的请求数 | Prometheus | 15s |

### 3.2 JVM 监控

| 监控项 | 指标 | 告警阈值 |
|--------|------|---------|
| 堆内存使用率 | 已用/最大 | > 80% |
| GC 暂停时间 | STW 时间 | P99 > 100ms |
| GC 频率 | GC 次数/分钟 | Full GC > 1次/分钟 |
| 线程数 | 活跃线程数 | > 500 |

### 3.3 中间件监控

| 中间件 | 监控项 | 指标 | 告警阈值 |
|--------|--------|------|---------|
| MySQL | 连接数 | 活跃连接/最大连接 | > 80% |
| MySQL | 慢查询 | 慢查询数/分钟 | > 10 |
| Redis | 内存使用 | 已用内存/最大内存 | > 80% |
| Redis | 连接数 | 活跃连接/最大连接 | > 80% |
| Kafka | 消息积压 | Lag | > 10000 |

### 3.4 业务监控

| 监控项 | 指标 | 数据来源 | 采集频率 |
|--------|------|---------|---------|
| 订单量 | 订单数/分钟 | 业务埋点 | 实时 |
| 支付成功率 | 支付成功/支付请求 | 业务埋点 | 1分钟 |
| 转化率 | 下单用户/访问用户 | 业务埋点 | 5分钟 |

## 四、告警设计

### 4.1 告警分级

| 级别 | 定义 | 通知方式 | 响应时间 |
|------|------|---------|---------|
| P0 | 严重影响业务，需立即处理 | 电话 + 短信 + 飞书 | 5分钟 |
| P1 | 影响部分用户或功能 | 短信 + 飞书 | 15分钟 |
| P2 | 潜在风险，需关注 | 飞书 | 4小时 |
| P3 | 信息通知 | 邮件 | 24小时 |

### 4.2 告警规则

| 告警名称 | 触发条件 | 级别 | 通知渠道 | 处理人 |
|---------|---------|------|---------|--------|
| 接口错误率过高 | 错误率 > 1% 持续 1 分钟 | P0 | 电话+飞书 | 值班人员 |
| 接口响应慢 | P99 > 1s 持续 3 分钟 | P1 | 飞书 | 开发负责人 |
| 数据库连接池满 | 连接数 > 90% | P0 | 电话+飞书 | DBA |
| 缓存命中率低 | 命中率 < 80% | P2 | 飞书 | 开发 |
| 消息积压 | Lag > 10000 | P1 | 飞书 | 开发 |

### 4.3 告警收敛

| 场景 | 收敛策略 |
|------|---------|
| 同一告警频繁触发 | 5分钟内只通知一次 |
| 关联告警 | 按服务聚合，只发一条 |
| 夜间告警 | P2 及以下延迟到工作时间通知 |

## 五、链路追踪

### 5.1 链路追踪架构

```
应用 -> Agent -> Collector -> Storage -> UI
```

### 5.2 链路采样策略

| 场景 | 采样率 | 说明 |
|------|--------|------|
| 正常请求 | 1% | 降低存储成本 |
| 错误请求 | 100% | 全量采集，方便排障 |
| 慢请求 | 100% | 耗时 > 1s 的请求 |

### 5.3 链路埋点

| 组件 | 埋点方式 |
|------|---------|
| HTTP 客户端 | 拦截器自动埋点 |
| RPC 调用 | Filter 自动埋点 |
| 数据库访问 | JDBC 驱动埋点 |
| Redis 访问 | 客户端拦截器 |
| MQ 消息 | Producer/Consumer 拦截器 |

## 七、排障手册

### 7.1 常见问题排查

| 问题现象 | 第一步看什么 | 关键日志关键字 | 常见原因 |
|---------|------------|---------------|---------|
| 接口超时 | 链路追踪找瓶颈 | `耗时` | 下游慢/数据库慢 |
| 接口报错 | 错误日志 | `ERROR` | 参数异常/外部服务异常 |
| 内存飙升 | JVM 监控 | `OutOfMemory` | 内存泄漏/大对象 |
| CPU 飙升 | 线程 Dump | - | 死循环/频繁 GC |

### 7.2 日志查询示例

```bash
# 按 traceId 查询完整链路
traceId: "xxx"

# 按接口查错误日志
level: ERROR AND api: "xxx"

# 按用户查操作记录
userId: "xxx"
```
